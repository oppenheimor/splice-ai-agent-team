# Frontend Design

在写代码前理解页面语境，并确定一个明确、可解释的视觉方向。

## 设计判断

- **目的**：页面解决什么问题，谁会使用，第一眼最需要理解什么。
- **气质**：根据需求选择具体方向，例如编辑感、玩具感、粗野主义、自然有机、工业工具、复古未来或克制奢华；不要默认套用同一种风格。
- **约束**：同时满足功能、性能、无障碍、桌面端与手机端要求。
- **记忆点**：明确一个最值得记住的视觉或交互特征，其他设计为它服务。

## 实现标准

- 建立清晰的信息层级、排版节奏和主次关系，布局可以不对称，但必须服务内容。
- 字体、颜色、间距、圆角、边框、阴影和动效形成同一套视觉语言；用 CSS 变量集中表达关键设计值。
- 动效集中在少数高价值时刻，并为 `prefers-reduced-motion` 提供降级；不要到处添加无意义漂浮和闪烁。
- 背景细节必须与主题相关，可以使用 CSS 图形、纹理、网格或层次，不要用装饰掩盖内容。
- 避免可替换到任何产品的模板：紫色渐变白底、无差别圆角卡片墙、到处都是胶囊标签、过度发光、默认 Hero 三件套，以及缺少语境的插画。
- 复杂度匹配设计方向：浓烈风格可以有更丰富的 CSS，克制风格则依赖精准的字号、行高、留白和对齐，不用装饰数量冒充设计质量。

## 许愿池运行边界

- 页面必须是单个自包含 HTML，CSS 与 JavaScript 内联。
- 禁止远程图片、字体、脚本、样式、iframe、npm 依赖和外部 API。
- 在可用的本地字体中有意识地组合 serif、sans-serif 或 monospace 字体族；不能为了追求特殊字体破坏离线与自包含要求。
- 优先用语义化 HTML、CSS 和少量原生 JavaScript实现，确保键盘可操作、对比度可读和窄屏可用。

完成实现后不要直接宣布完成，继续加载 `taste` 做生成后审查。
