# Grill Me

只有许愿池客户端上下文明确标记用户选择了“先拆解需求”后才能加载本 Skill。不要自行触发，也不要用于普通问答、排障、继续对话或局部调整。

1. 围绕目标用户、核心内容、视觉方向、关键交互、响应式要求和完成标准逐项访谈，直到双方形成共同理解。
2. 一次只问一个问题并等待回答；不要把多个问题堆在一条消息里。
3. 每个问题都给出一个基于当前上下文的推荐答案，让没有设计或编程经验的用户容易决策。
4. 能从已有对话或工作区文件确认的事实直接查找，不要反问用户；只有产品与设计决策需要用户选择。
5. 依赖前置决策的问题必须后问，沿着决策树逐层收敛，不重复已经确认的内容。
6. 未确认的内容已经不影响首版实现时，简短总结已确认边界，然后必须调用 `ask_question` 询问“需求边界已确认，可以开始实现吗？”。选项固定为 `{ id: "wish-creator-start-implementation", label: "开始实现" }` 和 `{ id: "wish-creator-continue-clarifying", label: "继续讨论" }`，不允许自由输入。
7. 只有用户选择“开始实现”后才能结束访谈并加载页面实现所需 Skill；选择“继续讨论”时继续逐项访谈，用户未确认前不要写页面。
