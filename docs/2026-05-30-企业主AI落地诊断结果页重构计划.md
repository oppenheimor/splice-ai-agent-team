# 企业主 AI 落地诊断结果页重构计划

## Summary

不保留历史兼容，不沿用“人格测评”技术债。将需求诊断完整改成“企业主 AI 落地诊断”：结果页顶部展示 **11 种简洁类型名称**，名称里不带“经营者”。底层字段、类型、DB 命名、聊天上下文统一改为 `operator` / `经营类型` / `AI 落地` 语义。第一轮同步重做 Q5/Q6/Q7 文案与权重，修复 Q10 互斥，并展示完整 5 个经营维度。

## Key Changes

### 1. 删除人格命名体系，改为简洁经营类型

移除或重命名所有面向业务的 `personality*` 概念，不再展示“深耕精算企业家实用派”这类组合名。

结果页顶部只展示 11 种简洁类型：

| 类型 | 解释 |
|---|---|
| 稳健深耕型 | 更适合先在熟悉业务里找 AI 提效点，不急着跨领域扩张。 |
| 增长探索型 | 对新机会敏感，适合用 AI 快速验证新渠道、新产品或新业务线。 |
| 经验判断型 | 决策依赖经验和商业直觉，AI 应先作为信息补充和复盘工具。 |
| 数据验证型 | 重视拆解、数据和可复制性，适合从流程指标和自动化看板切入。 |
| 系统重构型 | 倾向重建流程和组织能力，适合规划跨部门 AI 工作流。 |
| 快速试水型 | 愿意先跑 MVP，用小试点换反馈，适合轻量工具和短周期实验。 |
| 成本优先型 | 投入前先看 ROI，适合从降本、节省人力、减少重复劳动切入。 |
| 长期投入型 | 能接受阶段性投入，适合建设模板、数据资产和可复用系统。 |
| 风险防守型 | 关注稳定和边界，适合低风险场景、权限清晰、可控试点。 |
| 创新进攻型 | 愿意主动试错，适合探索新获客、内容、产品或交付模式。 |
| 平衡统筹型 | 各维度没有明显极端倾向，适合先明确业务优先级，再选 AI 切入点。 |

主类型选择规则：

- 取五维中偏差最大的维度作为主类型。
- 无维度偏差达到 20% 时，显示「平衡统筹型」。
- 并列时按企业 AI 落地优先级取：组织落地 → 投入心智 → 风险策略 → 判断方式 → 商业视野。
- 辅助倾向只进入解释段，不拼进标题。

### 2. 数据结构和 DB 彻底改名

不做兼容层，直接清理旧语义。

- `personalityCode` → `operatorCode`
- `personalityName` → `operatorTypeName`
- `personalityDefinition` → `operatorTypeDefinition`
- `aiLevel` 展示名改为 `aiAdoptionStage`
- `aiLevelLabel` → `aiAdoptionStageLabel`
- Prisma 字段同步改为 `operator_code`、`operator_type_name`、`ai_adoption_stage`
- Chat system prompt、history、result page、persistence、demo/mock 数据同步使用新字段
- 删除旧 `personalityEnglishName`，除非页面实际使用

需要新增 Prisma migration。既然不考虑历史兼容，迁移只保证新 schema 干净，不需要迁移旧数据展示语义。

### 3. 五维重命名为企业主经营语境

保留五维结构，改展示名和解释口径：

- 商业视野：深耕 ↔ 拓展
- 判断方式：经验判断 ↔ 数据验证
- 组织落地：系统重构 ↔ 快速试水
- 投入心智：成本优先 ↔ 长期投入
- 风险策略：风险防守 ↔ 创新进攻

结果页统一表达为“经营倾向”“AI 落地方式”“适合切入点”，不再使用“人格”“性格”“测试人格”等措辞。

### 4. 重做 Q5/Q6/Q7

Q5 改为测「投入心智」：

- A：先找一个能明确省人/省钱的环节，算清楚回报再投入 → 成本优先 1
- B：先投入一个能长期复用的基础能力，如知识库、流程模板、自动化工作台 → 长期投入 1
- C：先用小预算做试点，跑通效果后再扩大投入 → 成本优先 0.5 / 长期投入 0.5

Q6/Q7 改为测「试点风险偏好」，移除当前“业务被复制”的竞争防守语境。

Q6：

- A：先选低风险、低影响环节，明确权限和边界再试 → 风险防守 1
- B：只要方向有机会，先做一个小试点快速验证，边跑边控风险 → 创新进攻 1
- C：先建立评估清单和退出标准，再决定试点范围 → 风险防守 0.5 / 创新进攻 0.5

Q7：

- A：第一个 AI 试点效果一般时，先暂停扩大，复盘投入产出和风险 → 风险防守 1
- B：调整场景或流程，尽快换一个更有机会的切入点继续试 → 创新进攻 1
- C：保留有效部分，缩小范围继续观察 → 风险防守 0.5 / 创新进攻 0.5

移除 Q6 特殊计分规则，恢复 A/B/C 标准左右/平衡映射。

### 5. 结果页信息层级

页面顺序调整为：

1. 诊断结论：类型名称 + 一句话解释
2. AI 落地阶段：替代原「AI 层级」
3. 优先切入场景：来自 Q12 刚需方向
4. 经营决策画像：完整 5 个维度概览
5. 本周 / 本月 / 持续行动
6. 盲区与风险提示
7. 深度诊断 CTA
8. 建议路径：商业推荐降级到页面末尾

修复顶部五维概览只展示 4 个维度的问题，必须展示完整 5 个维度。

### 6. Q10 互斥规则

「纯人工无工具辅助」与其他工具互斥：

- 选择 E 时，清空 A/B/C/D。
- 已选择 E 后再选 A/B/C/D，自动移除 E。
- 计分时 E 作为“无常态工具”处理，不能与其他工具共同影响 AI 落地阶段。

LLM 仍只负责叙事增强，不负责改写类型名称、AI 落地阶段、五维分数。

## Test Plan

- 枚举 Q1-Q7，确认顶部类型名称只会落入 11 种。
- 单测 Q5/Q6/Q7 新文案对应的新权重。
- 单测 Q10 互斥交互和 `calculateAiAdoptionStage` 输入结果。
- 单测 Prisma DTO 转换，确认无旧 `personality*` 字段残留。
- 回归结果页：新答卷、本地 localStorage 结果、DB 保存、LLM 叙事成功/失败 fallback。
- 回归深度诊断 Chat，确认 system prompt 注入的是类型名称、AI 落地阶段和五维经营画像。

## Assumptions

- 不考虑旧历史数据兼容，可以新增 migration 并清理旧字段命名。
- 主用户是企业主 / 创业者。
- 结果页主目标是帮助用户理解自身 AI 落地状态。
- 深度诊断是主 CTA，商业推荐只作为末尾建议路径。
- 语气采用咨询顾问式，避免人格测试感和强销售感。
