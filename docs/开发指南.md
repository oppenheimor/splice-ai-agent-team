# 开发指南

本文档用于统一本地开发环境、Git 分支管理和常用脚本命令。

## 环境要求

- Node.js：使用 24.x，与 `package.json` 和 Dockerfile 中的构建环境保持一致。
- pnpm：项目使用 `pnpm-lock.yaml` 锁定依赖版本。
- Docker：用于启动本地 PostgreSQL。
- Git：用于分支管理和协作提交。

如果本机没有启用 pnpm，可以先执行：

```bash
corepack enable
corepack prepare pnpm@11.13.1 --activate
```

## 环境变量

本地开发使用 `.env`。首次启动前可从 `.env.example` 复制：

```bash
cp .env.example .env
```

当前需要关注的变量：

| 变量名 | 示例值 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://postgres:postgres@localhost:5432/splice_agent_team?schema=public` | Prisma 连接本地 PostgreSQL 的地址。默认值与 `docker-compose.dev.yml` 保持一致。 |
| `DEEPSEEK_API_KEY` | 留空或填真实密钥 | 调用 DeepSeek 模型时使用。本地不跑 AI 相关能力时可以暂时留空。 |
| `TAVILY_API_KEY` | 留空或填真实密钥 | 调用 Tavily Web Search 时使用；不使用联网搜索时可以留空。 |

注意事项：

- `.env` 和 `.env.local` 都属于敏感配置文件，已经被 `.gitignore` 排除，不要提交到仓库。
- 新增环境变量时，必须同步更新 `.env.example` 和本文档。
- 如果改了 `DATABASE_URL`，需要确认数据库容器、Prisma 配置和迁移命令使用的是同一套连接信息。
- 生产环境变量不由 GitHub Secrets 注入，统一保存在服务器 `/home/deploy/agent-team/.env`。修改和生效步骤见[生产回滚操作手册](./生产回滚操作手册.md#生产环境变量管理)。

## 一键初始化本地开发环境

推荐首次拉取项目后直接执行：

```bash
pnpm dev:init
```

这个命令会依次完成：

1. 如果 `.env` 不存在，则从 `.env.example` 创建。
2. 如果 `node_modules` 不存在，则执行 `pnpm install`。
3. 启动本地 PostgreSQL 容器。
4. 等待数据库就绪。
5. 执行 `prisma generate` 生成 Prisma Client。
6. 执行 `prisma migrate dev` 初始化或更新数据库结构。

初始化完成后启动开发服务：

```bash
pnpm dev
```

默认访问地址：

```text
http://localhost:3000
```

## 常用脚本

| 命令 | 用途 |
| --- | --- |
| `pnpm dev:init` | 一键准备本地开发环境：环境变量、依赖、数据库容器、Prisma Client、数据库迁移。 |
| `pnpm dev` | 启动本地开发服务。 |
| `pnpm build` | 构建生产产物。 |
| `pnpm start` | 启动生产模式服务，需要先执行 `pnpm build`。 |
| `pnpm lint` | 执行 ESLint 检查。 |
| `pnpm db:up` | 只启动本地 PostgreSQL 容器。 |
| `pnpm db:down` | 停止并移除本地 PostgreSQL 容器，但保留 Docker volume 中的数据。 |
| `pnpm db:generate` | 生成 Prisma Client。 |
| `pnpm db:migrate` | 执行 Prisma 开发迁移。 |
| `pnpm db:studio` | 打开 Prisma Studio 查看和编辑数据。 |

## 数据库与 Prisma

本地数据库由 `docker-compose.dev.yml` 管理：

- 容器名：`agent-team-postgres-dev`
- 数据库：`splice_agent_team`
- 用户名：`postgres`
- 密码：`postgres`
- 本地端口：`5432`

日常开发建议：

- 修改 `prisma/schema.prisma` 后，执行 `pnpm db:migrate` 生成并应用迁移。
- 只需要重新生成客户端时，执行 `pnpm db:generate`。
- 需要查看数据时，执行 `pnpm db:studio`。

## Git 分支管理

建议使用短生命周期功能分支：

```bash
git checkout main
git pull --rebase
git checkout -b feature/your-feature-name
```

分支命名建议：

| 类型 | 示例 | 场景 |
| --- | --- | --- |
| `feature/*` | `feature/diagnosis-history` | 新功能开发。 |
| `fix/*` | `fix/login-cookie` | 缺陷修复。 |
| `docs/*` | `docs/dev-guide` | 文档调整。 |
| `chore/*` | `chore/update-deps` | 工程配置、依赖、脚本等维护工作。 |

提交前建议至少执行：

```bash
pnpm lint
pnpm build
```

提交信息建议使用清晰的动宾结构，例如：

```text
docs: add development guide
chore: add local dev init command
fix: handle expired session redirect
```

## 本地开发流程

推荐流程：

1. 拉取最新代码：`git pull --rebase`
2. 初始化环境：`pnpm dev:init`
3. 启动服务：`pnpm dev`
4. 修改代码或文档。
5. 提交前检查：`pnpm lint` 和 `pnpm build`
6. 提交并推送功能分支。

## 常见问题

### 5432 端口被占用

如果本机已有 PostgreSQL 或其他服务占用了 5432，可以修改 `docker-compose.dev.yml` 的端口映射，同时同步更新 `.env` 中的 `DATABASE_URL`。

### Prisma 连接不上数据库

先确认容器是否启动：

```bash
docker compose -f docker-compose.dev.yml ps
```

再查看日志：

```bash
docker compose -f docker-compose.dev.yml logs postgres
```

如果 `.env` 中的 `DATABASE_URL` 被改过，优先检查端口、数据库名、用户名和密码是否仍然匹配 `docker-compose.dev.yml`。

### 想重新跑初始化

直接再次执行：

```bash
pnpm dev:init
```

该命令会复用已有 `.env`、`node_modules` 和数据库 volume，不会主动删除本地数据。
