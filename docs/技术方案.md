# 寻宝游戏 Agent 页面技术方案

## 1. 背景

平台目标是构建一个可持续扩展的 Agent Team：每个 Agent 都有独立页面、对话能力和差异化交互 UI，但聊天、流式协议、AGUI、hooks、SDK、会话存储等基础能力必须复用。

本期要实现「寻宝游戏 Agent」页面，路径为 `/agent-team/treasure/hunt`。参考项目为 `~/Desktop/pouch`，其中已有完整 chatbot、AGUI 能力和 `treasure-hunt-builder` 智能体提示词。

第二大脑参考：

- `~/wiki-global/wiki/concepts/agui-protocol.md`
- `~/wiki-global/wiki/products/vercel-ai-sdk.md`
- `~/wiki-global/wiki/patterns/tool-aware-streaming-ui.md`

核心判断：这个页面不是“聊天框 + 寻宝 prompt”，而是平台通用 Agent 架构下的第一个领域化 Agent 实例。

## 2. 技术原则

1. 新代码统一使用 TypeScript：`.ts` / `.tsx`。
2. 先抽通用架构，再实现寻宝业务。
3. 前端以 `UIMessage.parts` 为渲染中心，不以整段 Markdown 字符串为中心。
4. AGUI 工具输出通过 `toolName -> renderer` 映射渲染，新增工具不改聊天主流程。
5. `pouch` 的 `.js` 文件只作为迁移参考，不直接保留为新代码形态。
6. MVP 不引入 Prisma、复杂 Agent runtime 或后台配置系统，先跑通可复用闭环。

# 第一部分：通用架构抽象

## 3. 分层架构

```text
Route Layer
  页面路由、Agent 独立入口、首屏组合

Agent Definition Layer
  Agent Manifest、Prompt Builder、Tool Profile、Renderer Profile

Chat UI Layer
  AgentChatShell、Composer、ConversationPanel、MessagePartsRenderer

AGUI Render Layer
  通用工具 schema、toolName -> renderer、领域 renderer 扩展

Chat State Layer
  useAgentChat、会话创建/切换/删除、visitorId、本地持久化

Runtime Layer
  /api/agent-team/chat、AI SDK streamText、模型配置、消息压缩

Storage & Observability Layer
  MVP localStorage；后续数据库、analytics、eval、prompt version
```

这套分层的目标是让后续新增 Agent 时尽量只改三类东西：Agent Manifest、Prompt、必要的领域 renderer。

## 5. Agent Definition Layer

所有 Agent 先抽象成 Manifest，避免每个页面复制聊天逻辑。

```ts
type AgentManifest = {
  id: string;
  name: string;
  route: string;
  category: string;
  description: string;
  version: string;
  starterPrompts: string[];
  tools: AgentToolName[];
  rendererProfile: RendererProfile;
  promptBuilder: PromptBuilderName;
  memoryPolicy?: MemoryPolicy;
  evalCases?: EvalCase[];
};
```

MVP 注册两个 Agent：

- `requirements-diagnosis`
- `treasure-hunt`

后续新增 Agent 的标准路径：

1. 新增 Manifest。
2. 新增或复用 Prompt Builder。
3. 选择通用 renderer profile 或新增领域 renderer。
4. 页面只负责选择 Agent 和组合首屏，不负责实现聊天底层。

## 6. Chat UI Layer

通用聊天 UI 由 `AgentChatShell` 承担，页面只传入 Agent 和领域配置。

```tsx
<AgentChatShell
  agent={agent}
  emptyState={<TreasureHuntHero />}
  rendererProfile="treasure-hunt"
/>
```

`AgentChatShell` 内部组合：

- `ConversationPanel`：历史会话。
- `MessagePartsRenderer`：渲染 `UIMessage.parts`。
- `Composer`：输入、发送、停止生成。
- `ToolRendererRegistry`：按 tool name 分发渲染器。

这样 `requirements-diagnosis`、`treasure-hunt`、后续商业顾问类 Agent 都可以共享同一个聊天壳。

## 9. Runtime Layer

从 `~/Desktop/pouch/app/api/chat/route.js` 迁移为：

```text
POST /api/agent-team/chat
```

输入：

```ts
type ChatRequest = {
  agentId: string;
  conversationId?: string;
  visitorId?: string;
  messages: UIMessage[];
};
```

处理流程：

```text
route.ts
  -> validate request
  -> getAgentById(agentId)
  -> buildSystemPrompt(agent)
  -> pick tools by agent.tools
  -> compact UI messages
  -> streamText()
  -> toUIMessageStreamResponse()
```

MVP 沿用：

- `@ai-sdk/react`
- `@ai-sdk/deepseek`
- `ai`
- `streamText`
- `convertToModelMessages`
- `toUIMessageStreamResponse`
- `stepCountIs(4)`

这里的 Vercel AI SDK 定位是“流式协议 + 前端消息消费 + tool parts 承载”，不是完整 Agent 编排框架。

# 第二部分：寻宝游戏怎么做

## 11. 寻宝 Agent 定义

```ts
const treasureHuntAgent: AgentManifest = {
  id: "treasure-hunt",
  name: "大喜",
  route: "/agent-team/treasure/hunt",
  category: "surprise",
  description: "把心里的惊喜变成能照着做的寻宝活动方案包",
  version: "1.0.0",
  starterPrompts: [
    "我想给对象策划一个生日惊喜。",
    "帮我设计一个亲子寻宝游戏。",
    "我想求婚，但不想太俗。",
    "想约朋友聚会，别变成大家各自刷手机。"
  ],
  tools: [
    "askUserChoice",
    "showCards",
    "showComparison",
    "showChecklist",
    "showTimeline",
    "showScorecard"
  ],
  rendererProfile: "treasure-hunt",
  promptBuilder: "treasureHunt"

```

## 12. 寻宝 Prompt 迁移

从 `~/Desktop/pouch/lib/pouch/prompts.js` 中迁移 `treasure-hunt-builder`，拆到：

```text
lib/agent-team/agents/prompts/treasure-hunt.ts
```

必须保留的核心规则：

- 每轮只问 1 个问题。
- 信息不足时用 `askUserChoice` 引导，不一次性抛问卷。
- 方案选择不是预算选择，而是故事路径选择。
- 用户选择方案风格、预算、地点、难度、方案 A/B/C、展开模块时，必须调用 `askUserChoice`。
- 候选方案必须用 `showCards` 或 `showComparison`。
- 执行包必须用 `showChecklist`、`showTimeline` 等结构化组件。
- 普通回复保持短，完整交付包只在用户明确要求时展开。

寻宝工作流：

```text
开场
  -> 目标/对象确认
  -> 场景映射
  -> 每轮一个问题收集信息
  -> 信息确认
  -> 2-3 个候选方案
  -> 用户选择方案
  -> 预算/空间/难度/时间细化
  -> 精简执行包
  -> 按需展开关卡卡片、物料清单、时间线、心声卡
```

## 13. 页面结构

页面文件：

```text
app/agent-team/treasure/hunt/page.tsx
```

页面只做组合，不写聊天底层：

```tsx
export default function TreasureHuntPage() {
  const agent = getAgentById("treasure-hunt");

  return (
    <AgentChatShell
      agent={agent}
      emptyState={<TreasureHuntHero agent={agent} />}
      rendererProfile="treasure-hunt"
    />
  );
}
```

`TreasureHuntHero` 负责空会话体验：

- 展示“大喜”的角色感。
- 展示 4 个 starter prompts。
- 不解释复杂流程，不做营销 landing page。
- 直接引导用户说出“想给谁一个惊喜”。

## 14. 寻宝渲染策略

MVP 先用通用 AGUI：

| 业务场景 | 工具 | 渲染组件 |
|---|---|---|
| 单选/多选问题 | `askUserChoice` | `ChoiceTool` |
| 候选方案 | `showCards` | `CardsTool` |
| 方案对比 | `showComparison` | `ComparisonTool` |
| 物料和执行事项 | `showChecklist` | `ChecklistTool` |
| 执行时间线 | `showTimeline` | `TimelineTool` |
| 可行性评分 | `showScorecard` | `ScorecardTool` |

## 17. 验收标准

通用架构验收：

- `AgentChatShell` 不绑定寻宝业务。
- `useAgentChat` 可被任意 Agent 复用。
- `route.ts` 通过 `agentId` 选择 prompt 和 tools。
- `MessagePartsRenderer` 以 `parts` 为中心渲染。
- 新增 renderer 不需要修改 API route。

寻宝页面验收：

- `/agent-team/treasure/hunt` 可访问。
- 空会话展示“大喜”和 starter prompts。
- Agent 每轮只问一个问题。
- 选项通过 `askUserChoice` 展示和提交。
- 候选方案通过卡片或对比组件展示。
- 最终能输出清单和时间线。
- `pnpm lint`、`pnpm build` 通过。

## 18. 暂不做

- 不迁移 `pouch` 的 Prisma analytics。
- 不做登录态、多端同步和服务端会话库。
- 不做后台 Agent 配置系统。
- 不引入 LangGraph / pi-core / 自研复杂 runtime。
- 不在首期做 PDF 导出和分享链接。

这些能力等通用架构和寻宝 MVP 稳定后再进入下一轮。
