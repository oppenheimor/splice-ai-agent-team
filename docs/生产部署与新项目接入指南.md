# 生产部署与新项目接入指南

本文说明当前生产链路的边界、变量来源，以及后续项目复用这套发布方式时需要完成的配置。

## 当前生产链路

```text
GitHub main
  → 火山引擎托管构建
  → 火山引擎镜像仓库（不可变版本）
  → 最终阶段执行仓库脚本
  → SSH 到生产服务器
  → 候选容器预热与健康检查
  → prisma migrate deploy
  → Docker Compose 切换正式容器
  → Nginx reload 与线上验证
```

构建发生在火山引擎提供的临时资源中，生产服务器只拉取镜像并运行容器。生产机不再承担源码拉取、依赖安装和 Docker 构建，也不需要 GitHub Actions 自托管 Runner。

## 四类配置的存放位置

| 类型 | 变量或文件 | 存放位置 |
| --- | --- | --- |
| 火山系统变量 | `SCM_COMMIT_ID`、`PIPELINE_RUN_ID` | 火山引擎自动提供 |
| SSH 连接变量 | `SERVER_HOST`、`SERVER_USER`、`SERVER_SSH_KEY` | 火山流水线自定义变量；私钥必须设为隐私变量 |
| 非敏感部署配置 | 镜像仓库、远端目录、Docker 网络、容器名、健康检查 | 仓库的部署脚本和 Compose 文件 |
| 应用运行时变量 | `DATABASE_URL`、模型 API Key 等 | 生产服务器项目目录下的 `.env`，权限 `600` |

GitHub Secrets 不再参与生产发布。修改 GitHub Secrets 不会改变当前生产容器。

## 当前项目的版本化入口

火山流水线最终阶段只保留下面一条命令：

```bash
DEPLOY_IMAGE_TAG="${SCM_COMMIT_ID}-${PIPELINE_RUN_ID}" bash scripts/deploy-from-volcengine.sh
```

变量校验、SSH、部署文件上传和服务器发布都在仓库脚本中完成。流水线控制台不保存第二份完整部署脚本。

生产运行时必需变量登记在 [`deploy/required-env.txt`](../deploy/required-env.txt)。这里只允许填写变量名，禁止写入值。发布前置检查会读取该文件，并确认生产服务器 `.env` 中的对应变量存在且非空。

## 新项目接入清单

### 1. 准备镜像仓库

1. 在国内区域创建 OCI 制品仓库。
2. 开启镜像版本不可变，禁止覆盖已经推送的标签。
3. 记录完整仓库地址，例如 `REGISTRY/NAMESPACE/PROJECT`。

### 2. 准备生产服务器

服务器需要满足：

- Docker Engine 和 Docker Compose 可用；
- 部署用户属于 `docker` 用户组；
- 已登录目标镜像仓库；
- 已创建项目目录和权限为 `600` 的 `.env`；
- 已创建应用与 Nginx 共用的外部 Docker 网络；
- Nginx 通过容器服务名访问应用，且 Nginx 容器加入同一网络；
- 数据目录使用 Docker Volume 或独立持久化存储，不能写在容器可写层。

示例命令中的名称需要替换成新项目值：

```bash
mkdir -p /home/deploy/PROJECT
install -m 600 /dev/null /home/deploy/PROJECT/.env
docker network inspect app-network >/dev/null 2>&1 || docker network create app-network
```

### 3. 准备仓库文件

从 [`templates/volcengine-docker-ssh`](../templates/volcengine-docker-ssh/README.md) 开始，至少落实以下文件：

```text
Dockerfile
entrypoint.sh
docker-compose.yml
deploy/required-env.txt
scripts/deploy-from-volcengine.sh
scripts/deploy-production.sh
tests/deploy-*.test.sh
```

每个新项目必须显式替换：

- 镜像仓库地址；
- 生产服务器项目目录；
- Compose 服务名和正式/候选容器名；
- 外部 Docker 网络名；
- 应用健康检查；
- 数据库 migration 命令；
- Nginx 容器名及 upstream 验证地址；
- 必需生产变量名单。

健康检查和 migration 属于应用契约，不应复制后保持默认值。

### 4. 配置火山流水线

1. 创建 GitHub 服务连接并绑定仓库。
2. 代码源选择 `main`；首次接入可以先关闭自动触发，手工验证成功后再开启 push 触发。
3. 添加“镜像构建并推送”任务，构建上下文为 `.`，Dockerfile 为 `Dockerfile`。
4. 镜像版本设置为 `${SCM_COMMIT_ID}-${PIPELINE_RUN_ID}`。
5. 添加最终阶段“命令执行”任务，内容只保留版本化入口命令。
6. 添加 `SERVER_HOST`、`SERVER_USER`、`SERVER_SSH_KEY`；私钥保存为无密码 OpenSSH 私钥的单行 Base64，并开启隐私。

`SERVER_HOST` 和 `SERVER_USER` 不需要设为隐私。三者不需要开启动态输入。命令任务通过 Shell 环境读取这些变量，因此需要启用环境变量注入。

### 5. 首次发布验收

一次发布只有同时满足以下条件才算成功：

1. 构建产出的镜像标签与 commit 和流水线运行 ID 一致；
2. 候选容器完成应用预热和健康检查；
3. migration 成功；
4. 正式容器状态为 `healthy`，重启次数为 0；
5. Nginx 已 reload 并能访问新的容器 upstream；
6. 公网地址不返回 502；
7. 登录、核心写入流程和历史数据读取通过人工冒烟验证；
8. 服务器仍保留当前版本和最近两个历史镜像。

## 新增或修改生产环境变量

1. 在仓库 `.env.example` 登记变量名和安全示例。
2. 如果变量为启动必需项，同时加入 `deploy/required-env.txt`。
3. 在生产服务器项目目录的 `.env` 写入真实值并保持权限 `600`。
4. 使用当前不可变镜像重新执行 `deploy-production.sh`，让 Compose recreate 容器。

不要把运行时密钥放到 Dockerfile、Compose 的明文 `environment`、Git 历史或流水线命令中。

## 日常验证

仓库部署测试统一执行：

```bash
pnpm test:deploy
```

发布失败时先看失败发生在哪个门禁。候选预热或 migration 失败时，旧正式容器仍在服务；正式切换后的故障按照[生产回滚操作手册](./生产回滚操作手册.md)处理。
